# 我的空间

> 「我的空间」= 用户自管的一个目录。它既是 agent 干活时的**安全根**，
> 也是 keeper 作为**本地知识库 agent** 的**知识库本体**。
> 本文讲它的现状、边界，以及接下来两个方向的详细设计：
> **① 文件展示与编辑**、**② 向量跨模态搜索**（总纲见 [`roadmap.md`](roadmap.md)）。

---

## 一、它是什么

| 概念 | 位置 | 说明 |
|---|---|---|
| **「我的空间」** | `settings.yaml` 的 `user_space.path` | 用户指定的一个文件夹，跨会话共享 |
| **会话空间** | `~/.keeper/workspace/session/<session_id>/` | 每一轮的工作目录，agent 真正写文件的地方 |
| **agent 空间** | `~/.keeper/workspace/agent/<agent_id>/` | agent 级私有产物（插件索引、缓存） |

三者关系：**会话空间是工作面，「我的空间」是用户的地盘**。
用户在空间里放的东西 agent 能读能写；agent 在会话空间里产出的东西，用户能取回。

没配置时的回落：agent 用内置默认目录 `~/.keeper/workspace/user/default`（可写），
日志里会提示「未配置我的空间」。

### 安全边界

所有写操作（上传 / 下载 / 重命名 / 删除 / 打开）都先过 `resolve_target`：
路径必须落在空间根之下，否则 403。另有三道防线：

| 防线 | 落点 |
|---|---|
| 路径越界 | `zonefilesystem/space_ops.py::resolve_target` |
| 文件名穿越 | 上传只取 `Path(filename).name`，丢弃所有路径分隔符 |
| 目录删空保护 | 根目录不能被重命名 / 删除 |

## 二、现状：能力清单

### 文件操作（`zonefilesystem/space_ops.py`）

| 操作 | 落点 | 说明 |
|---|---|---|
| 浏览 | `browse.py` | 列目录、按类型分组 |
| 读 | `read_space_file` | 超 2MB 或二进制只回元数据、不回内容 |
| 原始字节 | `raw_from_space` | 供前端内联预览；HTML 套 CSP 挡住脚本外联 |
| 写（上传） | `upload_to_space` | 目标目录须在空间内 |
| 复制（空间内） | `copy_in_space` | 同名自动加 `(1)` 后缀，不覆盖；不能复制进自身子目录 |
| 复制（本机 → 空间） | `copy_from_local` | 桌面端用：系统剪贴板粘贴、系统对话框选文件 |
| 重命名 / 删除 | `rename_in_space` / `delete_in_space` | 根目录受保护；删除目录是递归的 |
| 新建目录 | `mkdir_in_space` | |
| 在文件管理器中打开 | `open_in_explorer` | macOS `open -R` / Windows `explorer /select` / Linux `xdg-open` |

### 展示与编辑（前端 `web/src/pages/UserSpacePage.tsx` + `components/`）

| 类型 | 展示 | 编辑 | 落点 |
|---|---|---|---|
| Markdown | GFM 渲染（表格、代码高亮） | ✅ 切「编辑/预览」，存回原文件 | `MarkdownView` |
| 纯文本 / 日志 / 配置 | Monaco 高亮 | ✅ | `viewers.ts` 分派 |
| 代码 | 按语言映射高亮 | ✅ | `monacoLang.ts` |
| JSON / YAML / XML / TOML / CSV / TSV | Monaco 高亮 | ✅ | `viewers.ts` |
| **Excel**（xlsx/xls/csv/tsv） | SheetJS 表格，多 sheet | ✅ 单元格可改，公式格式保留 | `SheetViewer` + `SheetGrid` |
| PDF | pdf.js 渲染 canvas，纵向翻页 | ❌ | `PdfViewer` |
| 图片 | 内联，缩放平移、双击复位 | ❌ | `ImageViewer` + `PanZoomStage` |
| HTML | 不内嵌，「在浏览器中打开」 | ❌ | — |
| 视频 | 浏览器原生播放器 | ❌ | — |
| 音频 / 其它二进制 / 超 2MB | 信息卡 + 下载 | ❌ | `viewers.ts` |
| 会话产物块 | chart / mermaid / table 内联渲染 | ❌ | `BlockView` |

### 表格预览的细节（已实现，值得单独记）

- 多 sheet 切换；双击 tab 重命名 sheet
- 单元格双击编辑，Enter 提交 / Esc 取消 / 失焦提交
- 只改目标单元格，其余**公式、格式、列宽原样保留**；改到数据区外自动扩 range
- 保存回原文件：csv/tsv 走文本写、xlsx/xls 走二进制写；600ms 防抖合并，切文件/卸载前强制落盘
- Excel 式行号列 + A/B/C 列头（sticky）、单击选中、拖拽框选、Esc 清除选区
- 数据区外多渲染 5×5 空白格，可双击直接填
- 上限：前 500 行 / 50 列
- CSV/TSV 先按 UTF-8 解码，出现替换符再按 GBK 兜底（防中文乱码）

### 与对话的衔接

| 能力 | 说明 |
|---|---|
| 引用文本 | 预览里选中文字 → 浮出「添加」→ 以 chip（`文件名 · 引用 N 字`）挂进输入框，发送时拼成「绝对路径 + 内容」 |
| 引用表格区域 | 拖选单元格 → 右下角「添加到对话」，区域用 Excel 语法（`A1:C5`，多 sheet 带 `Sheet2!A1:C5`） |
| `@我的空间` | 输入 `@` 唤出，**发送时**才展开成绝对路径；默认候选两项（我的空间 / 当前会话目录） |
| 快捷项自定义 | 设置弹窗「输入 @ 快捷项」段可增删改昵称与插入短语 |

### 桌面原生能力（`desktop/spaceFs.js` + `preload.js`）

「我的空间」的**人肉操作**走 Electron 原生，不走 Python HTTP 端点：

| 能力 | 实现 |
|---|---|
| 列目录 / 读 / 写 / 重命名 / 删除 / 复制 / 导入 | Node `fs`（`spaceFs.js`） |
| 系统文件对话框（选目录 / 选文件，多选） | `dialog`（`main.js`） |
| 在文件管理器中定位 | `shell.showItemInFolder` |
| 系统剪贴板（`Ctrl/Cmd+V` 粘贴导入） | `clipboard` |
| 前端调用通道 | `preload.js` 暴露的 `window.keeperSpace` |

路径安全由 `spaceFs.js::resolveSpacePath` 兜住：所有路径必须在空间根之下。

> 网页形态下这些原生能力不存在——界面会标「仅桌面端支持本地空间展示」，
> 「选择文件夹」按钮也是禁用的。

## 三、方向 ①：文件展示与编辑

### 要解决的问题

| 现在 | 问题 |
|---|---|
| PDF 只能看 | 没法标一句、圈一段、裁掉两页 |
| docx / pptx 打不开 | Office 文档是办公场景的默认格式，不能不支持 |
| 图片只能看 | 截图标注是高频动作 |
| 音频 / 视频没处理 | 会议录音、录屏是「我的空间」里的常见内容 |
| 2MB 以上直接拒绝 | 大日志、大 CSV 很常见 |
| 没有版本 | 改错了只能靠 agent 再改回来 |

### 设计

#### 3.1 统一的文档模型

各种格式 → 内部文档模型 → 回写原格式。这条路能避免「每个格式各写一套编辑器」：

```
原文件 ──解析──▶ 统一文档模型 ──渲染/编辑──▶ 统一文档模型 ──序列化──▶ 原文件
                  （块 + 样式 + 布局）
```

统一模型里要表达的东西：**块**（段落 / 标题 / 表格 / 图片 / 代码 / 公式）、
**行内样式**（加粗 / 斜体 / 颜色 / 链接）、**块属性**（对齐 / 缩进 / 列表层级）、
**批注**（锚点 + 作者 + 时间 + 内容）。

- 文本类（md / docx / txt）→ 块模型天然贴合
- 表格类（xlsx / csv）→ **不套块模型**，继续用 SheetViewer 的表格模型（它已经能保公式格式）
- PDF → **不是块模型**，是「页面 + 批注锚点」模型（见 3.3）
- 图片 → 位图 + 图层标注
- 音视频 → 转写文本 + 时间戳锚点

回写能力分级：**保真回写**（docx / xlsx / md）、**降级回写**（html / txt）、
**不回写**（pdf 只加批注层，不改原页面）。

#### 3.2 docx / pptx

- 解析与回写：`python-docx` / `python-pptx`（纯 Python，无外部依赖）
- 预览：docx 用块模型渲染成 HTML；pptx 按页渲染成幻灯片缩略图 + 单页展开
- 编辑：块级编辑（改文字、插图、调样式），尽量保真回写
- 不追求完全还原 Word 的排版引擎——**目标是「能读能改」，不是「像 Word」**

#### 3.3 PDF 深加工

PDF 不是块模型，是「页面 + 批注」：

- 渲染：pdf.js 已有，只缺**交互层**
- 批注：页面坐标锚点（page + x/y/w/h + 原文快照），支持高亮、矩形、箭头、手写
- 导出：把批注烘焙进新 PDF，或导出为「批注 + 原文件」的 sidecar（`.annotations.json`）
- 裁页 / 合并 / 拆页：用 `pypdf`（纯 Python）

#### 3.4 图片编辑

浏览器 canvas 就够，不必引服务端库：

- 裁剪 / 旋转 / 翻转（无损、可撤销）
- 标注层：矩形 / 箭头 / 文字 / 自由笔
- 保存：编辑结果**不覆盖原图**，另存为新文件（原图保留）——除非用户显式覆盖

#### 3.5 音视频

| 能力 | 方案 |
|---|---|
| 音频转写 | 复用模型的语音能力（走 OpenAI 兼容的 `audio` 接口）；产出带时间戳的转写文本 |
| 波形 | 前端用 `AudioContext` 解码画波形；点击波形跳到对应时间 |
| 视频抽帧 | 服务端用 ffmpeg（可走 `framework/` 自举的运行时）按固定间隔抽帧 |
| 视频字幕 | 抽帧 + 音频转写 → 生成 `.srt` / `.vtt` 旁挂 |

#### 3.6 大文件

现在 `read_space_file` 对 > 2MB 直接只回元数据。要做的是**分级降级**而不是硬拒：

| 大小 | 策略 |
|---|---|
| < 2MB | 整份读入（现状） |
| 2MB – 20MB | 文本按行分页返回；表格按行范围返回 |
| > 20MB | 只回元数据 + 首屏 N 行；提供「用 AI 处理」（把文件路径给 agent，而不是把内容塞进上下文） |

最后一条尤其重要：**大文件的正确姿势是让 agent 自己去读**（它有 bash），
而不是把内容搬进上下文。

#### 3.7 版本与撤销

- 每次保存产生一个版本：`~/.keeper/workspace/user/<space>/.keeper-versions/<relpath>/<ts>.bak`
- 版本保留策略跟随 `settings.yaml` 的保留天数
- 界面：预览头加一个「版本」下拉，可预览任意一版并回滚
- **回滚 = 再存一次**（保留历史，不做破坏性覆盖）

#### 3.8 diff 联动

现在只有 git 仓库内的文件能在产物卡片里看 diff。扩展到任意文件：

- 保存前生成与上一版的文本 diff（`difflib` 足够）
- agent 改过的文件在对话里显示 diff 摘要
- 二进制 / 表格类走「结构化 diff」（表格按单元格、PDF 按页）

### 实施顺序建议

| 阶段 | 内容 | 理由 |
|---|---|---|
| **P1** | 统一文档模型 + docx 读写 | Office 文档是最大缺口，块模型也能顺带服务 md/docx/html |
| **P2** | 图片编辑 + 版本/撤销 | 纯前端，无新依赖，见效快 |
| **P3** | PDF 批注 + 裁页 | 依赖 PDF 坐标模型，pypdf 纯 Python |
| **P4** | 大文件分级降级 | 主要是接口改造，不难但要改前后端协议 |
| **P5** | 音视频转写与抽帧 | 依赖模型语音能力与 ffmpeg，最重 |

## 四、方向 ②：向量跨模态搜索

### 要解决的问题

空间里现在**只能靠名字找**：

- 用户：目录树翻、或让 agent 用 `ls` + `grep`
- agent：只有 `bash`（`grep` / `find`），语义完全不通

「那个讲缓存穿透的文档在哪」——标题叫「缓存那些事」的 md 找不到；
「去年那个 Excel 里画了折线图的」更无从下手。

### 设计

#### 4.1 整体链路

```
空间文件
   │  ① 监听变更（mtime + size + inode 指纹）
   ▼
分块器 ──按类型分块──▶ 块列表
   │  ② 嵌入（本地模型优先）
   ▼
向量库（sqlite-vec / hnswlib）  +  全文索引（FTS5，复用记忆那套 jieba 分词）
   │
   │  ③ 检索：向量 + 关键词 + 结构化过滤 → RRF 融合
   ▼
search 工具 / @我的空间 候选 / UI 搜索框
```

#### 4.2 分块策略（按类型）

| 类型 | 分块 | 保留的元数据 |
|---|---|---|
| Markdown / 文本 | 按标题层级切（超长再按段落切） | 标题路径、行号范围 |
| 代码 | 按函数 / 类切（AST 优先，退化按空行） | 文件路径、符号名、起止行 |
| 表格 | 每 30–100 行一块，**带表头** | sheet 名、单元格范围 |
| PDF | 每页一块（含 OCR 文本） | 页码 |
| 图片 | 整图一块 | 路径、尺寸 |
| 音频 | 先转写，再按 30 秒窗口切 | 时间戳区间 |
| 视频 | 抽帧 + 音频转写，按时间切 | 时间戳区间 |

**表格块必须带表头**——否则「广州一日游」这一行脱离表头就没有意义。

#### 4.3 跨模态嵌入

| 模态 | 嵌入方式 |
|---|---|
| 文本 / 代码 / 表格 | 文本嵌入模型（代码与表格先转成带结构的自然语言） |
| 图片 | 视觉嵌入模型（图文共享向量空间，这样「画了折线图的表格」能命中「折线图」） |
| PDF | 抽文本 → 文本嵌入（有 OCR 则文本 + 图像双路） |
| 音频 / 视频 | 转写文本 → 文本嵌入（转写本身是 ASR，不做声纹向量） |

**统一向量空间是跨模态检索的前提**：所有模态的向量必须来自同一模型或对齐过的模型，
否则不同模态的向量不可比。

#### 4.4 混合检索

纯向量会漏掉精确词（文件名叫 `config.yaml` 这种），纯关键词又不懂语义。所以混合：

| 召回通道 | 负责 |
|---|---|
| 向量（ANN） | 语义相近 |
| FTS5 关键词 | 专有名词、路径、精确词 |
| 结构化过滤 | 路径前缀、扩展名、大小、修改时间 |

融合用 **RRF**（Reciprocal Rank Fusion）：各通道给一个排名，
按 `1/(k + rank)` 累加。RRF 不需要归一化分数，比加权求和更省事也更稳。

#### 4.5 接入 agent

新增工具 `search`（与记忆的 `recall` 并列，但搜的是空间里的文件）：

```json
{
  "name": "search",
  "description": "在「我的空间」里按语义搜索文件。query 用自然语言描述你想要的内容。",
  "args": {
    "query": "讲缓存穿透的那篇",
    "types": ["md", "pdf"],
    "path_contains": "docs/",
    "top_k": 8
  }
}
```

返回：文件路径 + 命中片段（带上下文）+ 分数 + 为什么命中。

**同时改 `@我的空间`**：现在的候选是固定两项（「我的空间」「当前会话目录」），
之后应变成「语义匹配出来的文件列表」——用户打 `@` 时看到的是**相关文件**而不是路径占位符。

#### 4.6 索引的工程问题

| 问题 | 处理 |
|---|---|
| **增量** | 文件指纹（mtime + size + inode）变化才重新嵌入；目录树刷新时做一次差集 |
| **删除** | 文件删了要同步删向量；否则会搜到不存在的文件（很伤信任） |
| **重复嵌入** | 内容哈希 → 向量缓存，同内容不同路径不重复嵌 |
| **成本** | 本地模型无 API 成本但吃 CPU；API 模型快但外传内容——**默认本地** |
| **大文件** | 按上面的分块策略切；超大文件可跳过并标记「未索引」 |
| **范围** | 只索引空间内；可配白名单目录、排除目录（`.git`、`node_modules`）、单文件大小上限 |
| **可暂停** | 索引是后台任务，要能停、能看进度、能只索引某个目录 |
| **可重建** | 索引是**派生数据**——和记忆的 FTS5 一样，删了能重建，不进版本库 |

#### 4.7 技术选型的取舍

| 选项 | 优点 | 代价 |
|---|---|---|
| `sqlite-vec` | 纯 SQLite，零服务，与现有 `keeper.db` 同栈 | 索引规模有上限（十万级块够用） |
| `hnswlib` | 纯内存，检索快 | 需持久化（`save_index`），与 SQLite 并存两套状态 |
| Chroma / Qdrant | 生态成熟 | 要额外起服务，违背「本机单用户、零外部依赖」的定位 |
| numpy + 暴力检索 | 最简单 | 万级块以上就慢 |

**倾向 `sqlite-vec`**：与 keeper 的存储栈一致，不用多一个进程或一份状态要同步。

嵌入模型同理：**默认本地**（如 bge-m3 / text2vec 之类的小模型），
API 嵌入作为可选项，且要在界面上说清「启用后文件内容会发给第三方」。

### 实施顺序建议

| 阶段 | 内容 | 理由 |
|---|---|---|
| **P1** | 文本类索引（md / txt / 代码）+ 向量库落地 + `search` 工具 | 先证明「语义能找到」，跨模态是增量 |
| **P2** | 混合检索（+ FTS5 + RRF）+ 结构化过滤 | 纯向量不够用，这一步决定好不好用 |
| **P3** | 表格 / PDF 分块与索引 | 复用已有解析能力（SheetJS / pdf.js 之外的 Python 侧） |
| **P4** | 图片视觉嵌入 | 需要图文同空间模型，依赖更重 |
| **P5** | 音视频转写后索引 | 依赖方向 ① 的转写能力 |
| **P6** | `@我的空间` 候选换成语义匹配 | 交互层的最后一环 |
